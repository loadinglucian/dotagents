# Structure and Style

## Recommended Document Shape

1. `# Title`
2. Table of contents (for longer docs)
3. Introduction (problem/benefit context)
4. Quickstart (feature docs)
5. Core sections (`##` / `###`) from basic to advanced

## Table of Contents Pattern

```markdown
<!-- toc -->

- [Main Section](#main-section)
    - [Subsection One](#subsection-one)

<!-- /toc -->
```

Use four-space indentation for nested items.

## Anchor Pattern

```markdown
<a name="section-name"></a>

## Section Name
```

## Voice and Tone

- Address reader directly (`you`, `your`).
- Prefer active voice and concrete actions.
- Keep tone professional but conversational.
- Use contractions naturally (`don't`, `you'll`, `it's`).

## Introduction Patterns

### Problem -> Solution

`While [context], you may [problem]. Thankfully, [product] allows you to [solution].`

### Conceptual framing

`[Feature] is like [familiar concept], allowing [benefit].`

### Feature intro

`[Product] includes [feature], which [benefit].`

## Transition Patterns

- `To get a better understanding of X, let's look at...`
- `Alternatively, you may...`
- `As you can see...`
- `Now that you have...`

## Paragraph Rules

- 2-4 sentences per paragraph
- one idea per paragraph
- explain first, then show code
